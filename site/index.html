How it works

One sentence. One check. Your “y”.

Agent-written tests encode whatever the code does, bugs included. A promise encodes what a person looked at and agreed to.

you: “perfect”→agent writes a check→thisisfine proves it→you: “y”→🔒 locked
🧪

Proven, not trusted

The check must pass on your code now, and fail on a version without the change while the app still boots. A check that can't fail is labelled 🟡 unproven.

🙋

Only you can lock it

Your reply goes through a hook, not through the agent. A whole-message yes (y, lock it, 👍, haan) locks it. “Yes but make it blue” doesn't.

🚧

Every stop is a gate

Before the agent can end a turn, every promise runs: in a real browser, against your API, or through your CLI. Broken? It's sent back with your words, the assertion and a screenshot or the HTTP exchange.

✍️

Signed and in git

Every lock is signed with Ed25519 and kept in an append-only ledger. thisisfine verify audits each one, on any machine.

⚡

Free when nothing changed

The gate hashes your working tree and skips the run if it matches the last green one. On the example shop, a passing gate takes about 1.3 s.

🗳️

Change your mind, out loud

/retire 3 we're dropping the badge asks you to confirm. Only your y retires a promise, never the agent's.

Install

Thirty seconds. Zero config.

You need Node 22.18 or newer, git, and a web app that starts with one command.

# in Claude Code /plugin marketplace add dadwritestech/thisisfine /plugin install thisisfine@thisisfine
# then, in your project /promise the cart badge shows how many items are in the cart
pi install npm:@dadwritestech/thisisfine
npm install -g @dadwritestech/thisisfine

Then copy four hooks into .codex/hooks.json: the Codex guide.

npx @dadwritestech/thisisfine status

In CI

A behaviour diff on every PR

The GitHub Action runs every promise the same way, fails the job if one is broken, and comments what the PR does to the promises, not just to the code.

# .github/workflows/promises.yml name: promises on: pull_request permissions: contents: read pull-requests: write jobs: thisisfine: runs-on: ubuntu-latest steps: - uses: actions/checkout@v4 - uses: actions/setup-node@v4 with: { node-version: 22 } - run: npm ci - uses: dadwritestech/thisisfine@v0

What it can't do

It makes cheating loud

thisisfine can't stop an agent that is determined to cheat. Here's exactly where the edges are.

  • Tamper-evident, not tamper-proof. A changed or deleted check, ledger or config blocks the next stop until thisisfine restore puts back what you confirmed.
  • Only as good as the check. It proves the check fails without the behaviour, not that it covers everything you had in mind. That's why a person has to say yes.
  • Web apps, APIs and CLIs. Checks in JS/TS, Python or Go, for Claude Code, Codex and pi. Other agents, libraries tested by import, and mobile or desktop UIs are out of scope for now.
  • Your app runs in your folder. If a check clicks Save, it really saves. propose names any file the app wrote, so you can point it at a scratch copy.

FAQ

Fair questions

Why not just ask the agent to write tests?

Because it writes tests for the code it wrote, and can edit them when they get in the way. A promise starts from you saying yes, is proven to fail without the behaviour, and is locked against edits.

Will it slow my agent down?

A turn that changed nothing costs nothing. A turn that changed code costs one app boot plus your checks, about a second for the example shop. A failing check takes longer, but that's the turn you wanted stopped.

What if a check is flaky or the app won't start?

Flaky checks warn and don't block. If the app can't start, the agent is blocked with the start error, because “couldn't check” isn't “fine”. Three identical blocks in a row and thisisfine hands the decision to you, so you're never stuck in a loop.

Do I need to know how to write tests?

No. You say “perfect” when something works and the agent asks if you want to lock it in. From then on, if it breaks it, it finds out before you do, and has to fix it before it can say it's done.

Why the name?

It's the face every coding agent makes while it reports success from inside a burning building. The phrase comes from KC Green's comic On Fire. thisisfine isn't affiliated with it, and the art here is original.
